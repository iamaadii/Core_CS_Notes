## **What Really Happens When You Make an HTTP Request?**
When you make an HTTP request, a series of steps occur behind the scenes to facilitate communication between your client (like a web browser or application) and the server hosting the resource you're trying to access. Here's a breakdown of what happens:

```text
Domain → IP → HTTP Data → TCP Segment → IP Packet → Frame → Network → Server
```

* **DNS** converts the domain name (e.g., `www.example.com`) into the server's **IP address (destination IP)**. For example, this could be the public IP address of an AWS EC2 instance or, more commonly, a load balancer/reverse proxy in front of it.

* The browser creates the **HTTP request** as data (text/bytes). HTTP itself is ultimately transmitted as bytes over the network.

* The browser asks the **operating system's networking stack** to send the request to the destination IP address.

* For **TCP-based HTTP**, the operating system establishes a TCP connection with the server using the **three-way handshake** (`SYN → SYN-ACK → ACK`). This ensures that both sides are ready to communicate.

* Once the TCP connection is established, the HTTP request data is passed to **TCP**. TCP divides the data into smaller pieces when necessary and adds a **TCP header** to each piece, creating **TCP segments**.

* The TCP header contains information such as the **source port** and **destination port**. The source port is usually a temporary (ephemeral) port chosen by the client, while the destination port is typically **80 for HTTP** or **443 for HTTPS**.

* Each TCP segment is passed to **IP**, which adds an **IP header** containing the **source IP address** and **destination IP address**. This creates an **IP packet**.

* The IP packet is then passed to the **Data Link layer**, which adds a frame header/trailer containing the **source and destination MAC addresses** (for Ethernet/Wi-Fi). This creates a **frame**. 

* The frame is transmitted over the physical network, such as **Wi-Fi or an Ethernet cable**, to the next network device (usually the client's router/default gateway).

* The frame may pass through **multiple routers and networks** before reaching the destination network. The IP source and destination generally remain the same end-to-end, while the **MAC addresses change at each local network hop**.

* When the server receives the frame, its network interface removes the Data Link layer information and passes the **IP packet** to the IP layer.

* The IP layer removes the IP header and passes the **TCP segment** to TCP.

* TCP uses the **sequence numbers** in the segments to put the data back in the correct order, handles retransmission if necessary, and delivers the reconstructed HTTP request data to the application (such as a web server).

* The web server/application processes the HTTP request, performs the required work, and generates an **HTTP response**, such as an HTML page or JSON data.

* The HTTP response travels back to the client through the same general layering process in reverse: **HTTP data → TCP segment → IP packet → Data Link frame → network → client**.

## **IP or logical Address**
- An IP address is a unique identifier assigned to each device connected to a network. 
- Assigned by `ISP`(Internet Service Provider) or network administrator.
- It serves two main purposes: 
  - identifying the host or network interface 
  - providing the location of the host in the network
- There are two versions of IP addresses: `IPv4` and `IPv6`.
  - `IPv4` addresses are 4-byte numbers typically represented in decimal format as four octets separated by periods (e.g., 192.168.1.1). 8 bits per octet. Each octet can range from 0 to 255, allowing for a total of approximately 4.3 billion unique addresses.
  - `IPv6` addresses are 128-bit numbers typically represented in hexadecimal format as eight groups of four hexadecimal digits separated by colons (e.g., 2001:0db8:85a3:0000:0000:8a2e:0370:7334). 
- Starting few bits of the IP address are used to identify the network, while the remaining bits are used to identify the host within that network. 

### Public & Private IP Address
- **Public IP** addresses are assigned to devices that are directly accessible from the internet. They are unique across the entire internet and are used for communication between devices on different networks. Public IP addresses are typically assigned by Internet Service Providers (ISPs) and can be either static (permanent) or dynamic (changing over time).
- **Private IP** addresses are used within private networks (like home or office networks). Assigned by the routers.


### Host
- A host is any device that has an IP address and can send or receive data over a network. This includes computers, servers, smartphones, and other devices connected to the internet.

## **Network**
- A network is a collection of interconnected devices that can communicate with each other. Suppose I have a mobile,laptop,computer connected to a router & router is connected to the internet. These connected devices form a network.

- Each network has a IP address which is helpful in deciding whether the destination device is in the same network or not.

- Within same network, devices can communicate directly with each other using their IP addresses without any internet. 

- If the destination device is in a different network, the request must be routed through a gateway or router to reach the destination.

- Router uses DHCP(Dynamic Host Configuration Protocol) to assign IP addresses to devices connected to it. 

- CIDR notation is a compact representation of an IP address and its associated network mask. It consists of the IP address, followed by a slash ('/') and a number(32 bit) which indicates the number of bits reserved for the network. Every device in the network has same first (number of bits) in their IP address. Remaining bits are used for host addresses within the network.

## **Types of Networks**
- There are several types of networks, based on their scope and coverage:
  - **Personal Area Network (PAN):** A network that is used for communication among devices close to one person. Example: Bluetooth connection between a smartphone and a wireless headset.
  - **Local Area Network (LAN):** A network that covers a small geographic area, such as a home, office, or building. LANs are typically used for connecting devices within a limited area. Example: Home Wi-Fi network, Office network.
  - **Campus Area Network (CAN):** A network that connects devices within a limited geographic area, such as a university campus or a corporate campus.
  - **Metropolitan Area Network (MAN):** A network that covers a larger geographic area than a LAN but smaller than a WAN, typically spanning a city or metropolitan area. 
  - **Wide Area Network (WAN):** A network that covers a large geographic area, such as a city, country, or even the entire world. The internet is an example of a WAN.

## **Subnet**
- A subnet (short for "subnetwork") is a smaller network within a larger network.
- It is created by dividing a larger network into smaller, more manageable segments. Subnets are used to improve network performance, enhance security, and simplify network management.
- Each subnet has its own unique network address and can contain multiple hosts (devices) within it. The subnet mask is used to determine which portion of an IP address represents the network and which portion represents the host within that network.

<br>

## **Subnet Mask**
- A subnet mask is a 32-bit number that divides an IP address into network and host portions. It helps determine which part of the IP address identifies the network and which part identifies the host within that network.
- It helps devices in determining whether a destination device is in the same network or not.
  - How it does:-
    - First, the device performs a bitwise AND operation between its own IP address and the subnet mask to determine its network address.
    - Then, it performs the same operation with the destination IP address and the subnet mask to determine the destination network address.
    - If the two network addresses match, the destination device is in the same network; otherwise, it is in a different network.

- For example, a subnet mask of 255.255.255.0 (or /24 in CIDR notation) indicates that the first 24 bits are used for the network portion, and the remaining 8 bits are used for the host portion.

## **ARP (Address Resolution Protocol)**
- ARP is a protocol used to convert an IP address to its respective MAC address within a local network. When a device wants to communicate with another device on the same network, it needs to know the MAC address associated with the destination IP address.
- The ARP process works as follows: 
  1. The device sends an ARP request, which is a broadcast message(done by the Router) asking "Who has this IP address from every other devices in the network? Please send me your MAC address."
  2. The device with the matching IP address responds with its MAC address.
  3. The requesting device receives the MAC address(through requested device via router) and can now communicate directly with the destination device using its MAC address.
- Every device maintains an ARP table, which is a cache that stores recently resolved IP-to-MAC address mappings, allowing devices to quickly look up MAC addresses without sending ARP requests for every communication.

## **Routing of HTTP Request & Response**
- When you make an HTTP request, the request is routed through various network devices, such as routers and switches, to reach the destination server. The routing process involves determining the best path for the data to travel based on factors like network topology, congestion, and routing protocols.
- The HTTP request is encapsulated into TCP segments, which are then encapsulated into IP packets. Each IP packet is routed independently through the network, and the routing devices use the destination IP address to determine the next hop for each packet.
- Once the HTTP request reaches the destination server, the server processes the request and generates an HTTP response. The response is then routed back to the client using the same process in reverse, ensuring that the data reaches the correct destination.

### TTL (Time To Live)
  - TTL is a value in the IP packet that prevents a packet from travelling around the network forever.
  - Every time the packet passes through a router, its TTL is decreased by 1. 
  - If TTL becomes 0, the router drops the packet. The router then sends an ICMP Time Exceeded message back to the source by adding source & dest IP. The source can use these TTL-expired messages to determine which router/hop caused the expiration.
    ![alt text](image-10.png)
  - Tools like traceroute / tracert use this behaviour to discover the routers (hops) between the source and destination. `tracert google.com` 


### How TraceRoute works
- It sends packets with different TTL values, starting from TTL = 1.
- The first router reduces TTL to 0, drops the packet, and sends back ICMP Time Exceeded → Hop 1. Futher traceroute will store IP of router which drops the packet.
- Then it sends another packet with TTL = 2 → reaches the second router → Hop 2.
- This continues until the packet reaches the destination.
- The time taken for each response is shown as the RTT.

## **TCP(Transmission control protocol)**

## **Anatomy of Segment(Headers + payload)**
- TCP sends data in the form of segments. Each segment having two part (header,payload).

### Headers
![alt text](image-20.png)
- contains control information needed to deliver data reliably.
- has a minimum size of 20 bytes and can be up to 60 bytes when options are present.
- `source port` tells the port number of the application that sent the data. size is 2-byte
- `destination port` tells the port number of the application that should receive the data. size is 2-byte.
- `sequence number` is of 4-byte 
- `aknowledgement number` is of 4-byte 
- `Data offset` represent the starting point of payload. It tells the receiver the size of the TCP header. Because TCP header size is not always 20 bytes. It can become larger when options are present. It can be `>=5`. `1 dataOffset = 4bytes`
- `Reserved` is a `3-bit` space reserved for future use.
- `TCP flags`:- 1 bit each. Can be either 0(not set) or 1(set).
    - `CWR — Congestion Window Reduced` used by sender to tell reciever that i'm reducing the sending rate/window because of network congestion.
    - `ECE — ECN Echo` used by reciever to tell the sender to reduce the sending the rate.
    - `URG — Urgent` It tells TCP that some data should be treated as urgent.
    - `ACK — Acknowledgment` Used by reciever to acknowledge received data.
    - `PSH — Push` Tells TCP to push the received data to the application without unnecessarily waiting for more data.
    - `RST — Reset` Used to immediately terminate/reset a TCP connection.
    - `SYN — Synchronize` Used to start a TCP connection.
    - `FIN — Finish` Helps perform a graceful TCP connection termination.
- `Window size` represents the capacity of data reciever can handle. Used for flow control. size is 2-byte
- `Checksum` Used to detect whether the TCP segment was corrupted during transmission. Sender calculates the checksum and puts it in the header. Receiver calculates it again and compares. If the values don't match: Data was probably corrupted.

- `options`  size can be upto 40bytes. Used for adding Optional information for TCP. Possible Header Options are, MSS (Maximum Segment Size), Timestamp, Window Scale, Selective Ack.

### Payload
- The payload is the actual data being carried by a TCP segment.

## **PMTUD (Path MTU Discovery)**
- Whenever data travels over the network it goes through many routers & every router have a MTU & in some cases it's less than the sender's MTU which can cause fragmentation. So prevent from this first we find the `PMTU`(smallest MTU along the path). 
- PMTUD is used to detect minimum MTU among all the devices from sender to reciever which helps in preventing IP packets form fragmentation.
- How PMTUD works:-
  - Sender starts with larger IP packets by setting DF(don't fragment) flag present inside IP packet headers. 
  - Routers drop if `packet size > router MTU` & sends ICMP "Fragmentation Needed". 
  - Sender reduces packet size.
  - Continues until packets pass successfully

## **Flow-control in tcp**
- Flow control is a mechanism used by TCP to control the amount of data sent by the sender.
- Its main purpose is to prevent a fast sender from overwhelming a slow receiver.
- TCP uses the Receive Window (rwnd) for flow control.

### Receive Window (rwnd) (Known through 3-way handshake)
- The receiver has a buffer(in bytes) where incoming TCP data is temporarily stored.
- The receiver tells the sender how much free buffer space it currently has.
- This value is called the Receive Window (rwnd).
- It is advertised in the Window Size field of the TCP header.
- As size of window is `2-bytes` so the maximum amount of data which can be received by reciever will be `65kb` at a time which is not great as it will take a lot of time. To solve this we use `window scaling.`

### How TCP Flow Control Works?  

![alt text](image-26.png)
- The receiver tells the sender it's window size.
- The sender can send data up to the allowed window.
- After recieving reciever sends ack(ackNumber + currentWindowSize) back to sender.
- If the `currentWindowSize=0` sender will wait for the another ack back from the reciver.

## Window Scaling Factor
- Solves the 65 KB TCP window limitation.
- Value ranges from 0 to 14 
- Sends during TCP three-way handshake in the options field of tcp headers.
- Used to get Actual/Effective window size
  ```
   Actual Window size = Window Size * 2 ^ (Window scaling factor)
  ```

## **Congestion control in tcp**
- Congestion Control is a mechanism that prevents the network (routers and links) from becoming overloaded  
- The receiver's window size (`rwnd`) may be larger than what the network can currently handle. If the sender sends data according to `rwnd` alone, the network may become congested, which can cause packet loss.
- To prevent this, TCP limits the amount of unacknowledged data using both the receiver's capacity and the network's capacity.
- Therefore, the effective sending window is: `min(rwnd, cwnd)`
  - `rwnd` → Receive Window; represents how much data the receiver can currently accept.
  - `cwnd` → Congestion Window; represents how much data TCP currently allows to be in transit based on network congestion.

<br>

## **Algorithms used by tcp to find cwnd**

### TCP Slow Start & Congestion Avoidance : 
- Starts slow and gradually increases the CWND size (approx. doubles every RTT)

## **How TCP Detects Congestion(packet lost)?**
### Retransmission Timeout (RTO)  
- Sender transmits a segment 
- Expected ACK does not arrive before the timeout expires 
- TCP assumes severe congestion or packet loss 
- Considered a strong indication of congestion 

### Triple Duplicate ACKs 
- Receiver repeatedly acknowledges the same missing packet  
- Sender receives 3 duplicate ACKs for the same sequence number 
- TCP assumes a packet was lost due to congestion


<br>

## **How congestion window behaves after detecing congestion?**
- For both RTO & triple duplicates acks congestion window behaves differently.
- For triple duplicates acks conjestion tcp sets `ssthresh = cwnd / 2` & `cwnd = cwnd/2` & tcp shifts  to  congestion avoidance.
- In case of RTO, tcp sets `ssthresh = cwnd / 2` & `cwnd = 1` & tcp shifts to slow start.

<br>

## **How TCP can detect Congestion before it happens?**  
### ECN (Explicit Congestion Notification) 
- Traditional TCP detects congestion after packet loss occurs
- ECN allows routers to indicate congestion before dropping packets 
- Helps reduce unnecessary packet loss and retransmissions.
- Whenever any intermediate device detects congestion can happens it first sets the `ECN` flag(present in IP header) & then send it to reciever.
- After that reciever inform about this conjestion to sender by using `ECE` flag (present in segment header) during 'ack'.
- Then sender reduces `cwnd` & sets `cwr` flag(present in segment header). 
- During 3-ways handshake both `ece` & `cwr` sets by-default which represent device supports `ECN`.

## **How dns works?**
![alt text](image-34.png)
- User enters or searches for a website in the browser. The browser needs the **IP address** of the server hosting that website.
- The browser first checks its **DNS cache**.
  - If the IP address is found → use it.
  - Otherwise → check the **OS DNS cache**.
  - If found → use the IP address.
  - Otherwise → send a request to a **DNS resolver**.
- The request is sent to a **DNS Resolver**. It is usually provided by:
  - ISP
  - Router
  - Public DNS service
- The resolver first checks its **own cache**.
  - It may have cached information such as the IP address or DNS server information.
  - If the required answer is found → it returns the IP address.
  - If not → it performs a DNS lookup by contacting other DNS servers.
- First, the resolver contacts a **`Root DNS Server`** to find the appropriate **`TLD (Top-Level Domain) server`**, such as `.com`, `.in`, `.org`, etc.
- Then, the resolver contacts the **`TLD Server`** to find the **`Authoritative DNS Server`** responsible for the requested domain.

- Finally, the resolver contacts the **`Authoritative DNS Server`**, which contains the actual DNS records for the domain.
  - It returns the requested DNS record, such as the **IP address**, along with its **TTL (Time To Live)** in seconds. TTL tells the resolver how long the result can be cached. 

- The resolver sends the IP address back to the user's computer.
  - The result is usually cached for the specified TTL so that the same lookup does not need to be performed again immediately.

- Now the browser knows the **IP address** of the server.
  - It can establish a connection with the server and request the website.

## **DNS record**
- DNS records are instructions stored on `authoritative servers` that tell the internet how to route traffic for a domain name.
- DNS records is like a contact list on your phone. They match human-friendly website names (like example.com) to the machine-friendly IP addresses and servers that run websites
- Below are some types of records:-


## **`A` record**
- A = Address
- Maps a domain name to an IPv4 address.
- What is IPv4 address of wajeshubham.in? DNS Replies: 3.111.187.148 (It may return one or more IPv4 addresses) 
- Multiple A records can exist for a single domain (for load balancing/failover/high availability)

## **`AAAA` record**
- Maps a domain name to an IPv6 address.
- What is the IPv6 address of wajeshubham.in? DNS Replies: 2606:4700:90d2:7cbc:c29e:8b4:5ff2:75c4 (It may return one or more IPv6 addresses)  
- Multiple AAAA records can exist (for load balancing/failover/high availability)

## **`MX(Mail Exchange)` Record**
![alt text](image-35.png)
- Used by SMTP(simple mail transfer protocols) servers during email delivery. 
- Lower the priority value of a MX record higher the preference. 
- Multiple MX records can exist for redundancy and failover.
- MX records contain hostnames, not IP addresses.
- SMTP servers perform A or AAAA lookups on the MX hostname before connecting.
- If the highest-priority mail server is unavailable, the next MX record is tried 
- MX records do not store emails, they only show where emails should be delivered
- Multiple MX records with the same priority value can be used for load balancing


## **`CNAME` Record**  
- stands for Canonical Name Record 
- Maps one domain/subdomain to another domain name., not directly to an IP address 
- The target hostname/domain must eventually resolve to an A record or AAAA record
- Target domain must have a `A` or `AAAA` record. 

```
Example: www.example.com → example.com
```
- When a user requests: `www.example.com` browser will ask for 'A' record from DNS. Then DNS will tell i don't have but i have `cname` record.
- DNS follows the `CNAME` to: `example.com` and then looks for its IP address.


## **`NS(Name server)` Record**
- Specifies the authoritative DNS servers for a domain.
- These servers contain the DNS records for that domain.
- Without NS records, resolvers would never know where to find a domain's DNS records 
- A domain usually has multiple name servers for redundancy and high availability
```
Ex:- example.com → ns1.example-dns.com
    example.com → ns2.example-dns.com
```

### DNS Delegation
- DNS delegation means **giving responsibility for a domain/subdomain to another DNS server**.

### What happens when you search a website?
- Suppose you enter: `www.example.com`. The dns resolver doesn't know the IP.
- First, resolver asks from `root dns server`. Root says:
  - "I don't know `example.com`,
  - but `.com` is handled by this `TLD(Top-level domain) server`
- Again, resolver asks from `.com` TLD server. The TLD server says:
  - "I don't know the IP of `www.example.com`,
  - but `example.com` is managed by: these `Authoritative DNS Server` (`ns1.example.com`, `ns2.example.com`). 
  - THIS IS `DELEGATION`.
- Resolver again asks `Authoritative DNS Server`(ns1.example.com) to get the actual dns record.


## **`TXT(text)` Record** 
- Stores text information associated with a domain.
- Originally designed for human-readable notes
- Now, commonly used for Domain ownership verification,SPF email authentication
- A domain can have multiple TXT records 
- TXT records don't affect website routing.

### Text records used for spf(sender policy framework)
- SPF allows a domain owner to specify which mail servers/IP addresses are allowed to send emails on behalf of their domain. The receiving mail server checks the sender's IP against this SPF policy. 
![alt text](image-36.png)

### Steps how it checks:-
- Step-1: Email is Sent
  - The sender sends an email from: `hello@wajeshubham.in`
  - The email is sent to: `john@gmail.com`
  - The receiving mail server (Gmail) receives the email.
- Step-2: Gmail Checks the SPF Record
  - Gmail finds the domain of the sender: `wajeshubham.in`
  - It asks DNS for the **TXT records** of this domain `DNS Query: TXT wajeshubham.in`
  - DNS returns the TXT records, including the SPF record:
    ```text
      v=spf1
      ip4:64.202.168.0/24
      ip4:97.74.135.0/24
      -all
    ```
- Step 3 — SPF Record is Identified
  - Gmail looks through the `TXT records` and identifies the SPF record.
  - The SPF record tells Gmail which IP addresses are allowed to send emails for `wajeshubham.in`.

- Step 4 — Check Included SPF Records
  - If the SPF record contains an `include`, Gmail also checks the SPF record of that domain `include:secureserver.net`
  - Gmail asks DNS for: `TXT secureserver.net`
  - DNS returns the SPF information of `secureserver.net`.

- Step 5 — Check Sender's IP
  - Gmail gets the IP address of the server that actually sent the email: `64.202.168.11`
  - It checks whether this IP belongs to any of the IP ranges allowed by the SPF policy.
  ```
    64.202.168.0/24
    97.74.135.0/24
  ```
- Step 6 — SPF Result
  - If the sender's IP belongs to an authorized IP range: `SPF → PASS` The sender's server is authorized to send email for the domain.
  - If the IP does not belong to any authorized range: `SPF → FAIL` The sender's server is not authorized to send email for the domain.

## **`PTR(Pointer record)` record**
- PTR records are used for reverse DNS lookups 
- PTR records map IP Address -> Hostname 
- Opposite of A and AAAA records 
- Usually configured by the IP address owner, not the domain owner (Cloud Providers/ISPs etc) 
- A missing PTR record does not stop a website from working, but it can negatively affect the reputation of a mail server sending emails into the spam.
